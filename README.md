## Recommendations
- Keep the default values
- Focus on internal routing
- Use [Surrealist](https://surrealdb.com/surrealist)
- Use a Cloudflare proxy domain for public routing (HTTPS)
- Read their [Documentation](https://surrealdb.com/docs) and the [4.0 release notes](https://surrealdb.com/releases/4.0)
- Upgrade your SDK before connecting: 4.0 refuses some value formats older SDKs send

## Connecting from another service
The service name contains a dot, so quote it in reference variables:

    ${{"SurrealDB 4.x (Latest)".SURREAL_PRIVATE_URL}}

A new instance starts with a `main` namespace and a `main` database.

## Upgrading from 3.x
SurrealDB 4.0 refuses to start on a 3.x datastore, so don't just change the image on an existing 3.x service.
- Recommended: deploy this template alongside it, then `surreal export` from the 3.x instance and `surreal import` into the 4.x one.
- In place: back up the volume, set `SURREAL_EXPERIMENTAL_UPGRADE_FROM_3X=true` and switch the image to `surrealdb/surrealdb:v4`. This is one-way (3.x can't open the files afterwards) and needs free space for a second copy of the data.
